# 计算模块设计说明

## 1. 需求分析

程序只接受三个命令行参数：

```text
python main.py <原文绝对路径> <抄袭版绝对路径> <答案文件绝对路径>
```

核心输出是一个取值范围为 `0.00` 到 `1.00` 的浮点数。程序不能联网，
不能读写参数之外的文件，并且需要在 5 秒内完成常见测试文本的计算。

## 2. 模块划分

| 模块 | 主要职责 |
| --- | --- |
| `main.py` | 作为命令行入口调用 `run()` |
| `plagiarism/cli.py` | 解析参数、组织计算流程、统一处理异常 |
| `plagiarism/io_utils.py` | 读取文件、识别编码、写入答案 |
| `plagiarism/normalization.py` | 提取 HTML 正文、Unicode 归一化、去除标点空白 |
| `plagiarism/similarity.py` | 生成字符 n-gram、计算稀疏向量余弦相似度 |
| `plagiarism/errors.py` | 定义可预期的用户级异常 |

各模块之间只通过简单函数和不可变配置对象连接，核心计算不依赖文件系统，
因此可以直接使用字符串进行单元测试。

## 3. 算法设计

### 3.1 文本归一化

1. 如果输入是被浏览器另存为 GitHub 网页的 HTML，先提取表格中真正的
   文本行，避免导航栏和脚本噪声。
2. 使用 Unicode `NFKC` 统一全角字符和兼容字符。
3. 进行 `casefold()`，消除大小写差异。
4. 删除空白和标点，只保留字母、数字和汉字。

### 3.2 多阶 n-gram

对归一化文本分别生成 1-gram、2-gram 和 3-gram：

```text
文本：论文查重
1-gram：论、文、查、重
2-gram：论文、文查、查重
3-gram：论文查、文查重
```

不同阶数承担不同作用：

- 1-gram 对插入和删除更宽容，避免删掉少量字后分数骤降。
- 2-gram 能识别常见搭配和局部顺序。
- 3-gram 对语序变化更敏感，可以识别简单打乱文本的行为。

### 3.3 加权余弦相似度

每个阶数都由词频向量计算余弦相似度，然后按以下权重融合：

```text
score = 0.15 * cosine(1-gram)
      + 0.45 * cosine(2-gram)
      + 0.40 * cosine(3-gram)
```

权重不是凭空设定的：2-gram 和 3-gram 合计占 85%，以保证对顺序变化的
敏感度；1-gram 保留 15%，用于抵抗少量增删造成的碎片化。该组合在课程
样例上能够稳定体现“增加/删除约 0.8 含量，打乱越多分数越低”的趋势。

### 3.4 关键函数

| 函数 | 输入 | 输出 | 说明 |
| --- | --- | --- | --- |
| `normalize_text(text)` | 原始字符串 | 归一化字符串 | HTML 兼容和统一字符表示 |
| `count_ngrams(text, n)` | 文本、阶数 | `Counter` | 统计重叠字符片段 |
| `_cosine_similarity(left, right)` | 两个稀疏向量 | 浮点数 | 只遍历较小字典，减少查询次数 |
| `calculate_similarity(a, b)` | 两篇文本 | `[0, 1]` 分数 | 加权融合三个阶数 |
| `run(arguments)` | 命令行参数 | 进程退出码 | 统一异常输出和答案文件写入 |

## 4. 流程图

```mermaid
flowchart LR
    A[main.py 解析参数] --> B[读取原文和抄袭版]
    B --> C[提取 HTML 正文并归一化]
    C --> D[生成 1/2/3-gram]
    D --> E[计算余弦相似度]
    E --> F[加权融合]
    F --> G[写入两位小数答案]
```

## 5. 复杂度与资源

设两篇文本长度分别为 `m` 和 `n`，最多计算三个固定阶数：

- 时间复杂度：`O(m + n)`，常数约为 3 次 n-gram 统计。
- 空间复杂度：`O(m + n)`，只保存字符片段计数和归一化文本。

因此程序不会出现 `difflib.SequenceMatcher` 在大文本上的平方级退化。
实测 42,465 个归一化字符约 0.16 秒，远低于 5 秒限制。

## 6. 异常设计

异常被区分为命令行、读取、解码和写入四类，并且都在 `cli.run()` 中
转换成可读错误信息。错误发生时不创建答案文件，避免产生误导性结果。
